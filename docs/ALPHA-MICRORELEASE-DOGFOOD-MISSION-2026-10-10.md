## User feedback architecture (explicit UX intent)

- Small accessible `🐛` or `Reportar` control in the **web portal chrome around the editor**, not an SVG joint or intrusive overlay. Opens a compact panel where the user chooses bug/idea/acro/other, types description and sees exact `channel + revision + viewport + session ID`, with submit confirmation ID (e.g. `AL-...`).
- Client-side **bounded opt-in interaction recorder**, designed to answer "what gestures immediately preceded the bug": capture only **app semantic event types + timestamps relative to session + non-sensitive geometry/target identities + selected joint IDs + tool/axis/timeline key IDs/relative times + bounded viewport/zoom**, and safe JS error tags; do **NOT** record raw keypresses, text field contents, form input, passwords, tokens, localStorage dumps, network response bodies, contact details, clipboard, private files, raw stack traces or personal IDs. Keep memory ring cap (~120–200 actions / last 1–3 min / limited bytes), scrub unexpected strings, cap event rate. Recording OFF by default, clearly marked when ON.
- Optional **Save Session** locally (small JSON evidence export) and/or bounded local session persistence with user-visible clear/delete; no silent remote upload. Choose storage TTL/cap and distinguish anonymous ephemeral session ID from identity. Enable opt-in **Attach recent diagnostic log** (checkbox off by default) to one submitted report, preview count/categories before sending; preserve ability to send message without logs.
- In editor iframe, cross-document messages only same-origin, only known `type` and minimal whitelisted schema, validate event.origin and source; do not disable CSP, do not leak state from Beta or another Alpha revision. When instrumenting self-contained SVG is needed, keep user-facing recording explicit, provenance/revision pinned, no release from uncommitted files.
- Backend: extend already existing `/api/feedback` schema with bounded optional `channel/revision/variant/session metadata/actions`, enforce strict JSON/body sizes and server-side filtering, reject unknown huge/sensitive payload, same-origin check/rate-limit/anti-spam. Append private JSONL under service state root not public/Git (mode 0600), no IP saved. Reports remain `triage:unreviewed` until a Pi worker reproduces failure; **confirmed DogFood** is then a separate redacted Git/OpenSpec markdown entry and RED test, linked by issue ID and exact SHA. Never auto-create source-level bug-fix work directly from untrusted reporter content; no PII copy into Git or LLM prompts.
- Fail safely: a failed feedback post must not disrupt editor or corrupt saved poses; alert user and allow copying report. Local recording never prevents gestures. Include tests for opt-out, partial consent, error rejection, origin/CSP, legacy feedback payload, empty report, export, reload, mobile form, submit → persisted JSONL and no private content public.
